## Phase Goal

**ROADMAP `**Goal:**` line, verbatim:** The attacker faces an accuracy-drop target that scales with the leverage it actually has this round, resolved everywhere through one function, and the bottom rung is confirmed measurable before anything is built on it.

> **MVP_MODE note (surfaced, not invented):** this Goal line is not in `As a / I want to / so that` user-story form. Per the MVP enrichment rules the planner does not invent a story. Run `/gsd mvp-phase 01` if you want the ROADMAP goal rewritten as a user story; nothing in this plan depends on it.

<objective>
Prove the whole budget → target path end to end on one budget, then harden it across the ladder.

This is the tracer for Phase 1: `FLArmsRaceEnv.begin_round()` samples a poison budget, `_round_goal()` turns that budget into a target through one function in `rl/rewards.py`, and the resulting goal dict reaches all three consumers — the attacker reward, the schedule's win gate, and the attacker prompt — with the same number in it. Nothing else in the phase means anything until that path is real.

Purpose: without a reachable, budget-scaled target every GRPO rollout scores ~0, group advantages collapse, and the gradient step is skipped (PROJECT.md §Context). This plan makes the target a deterministic function of the round's actual leverage.

Output: `DEFAULT_TARGET_LADDER` + `target_for_budget()` in `rl/rewards.py`; `self.target_ladder` load, key normalization and startup coverage validation in `FLArmsRaceEnv.__init__`; a rewritten `_round_goal()`; the retired per-round target-sampling attributes gone from the env; and `tests/test_target_ladder.py` carrying the end-to-end agreement proof and the ladder edge cases.
</objective>

<threat_model>

This is a research testbed for adversarial ML, not a network-facing service. There is no user input surface, no authentication, no persistence of third-party data, and no network listener. The ASVS-L1-adjacent surface that genuinely exists is **config-as-input** — `configs/base.yaml` is parsed by PyYAML into values that drive control flow and reward arithmetic — and **fail-closed startup validation**. Web-application threats are not modelled because they do not exist here.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `configs/*.yaml` → `FLArmsRaceEnv.__init__` | Operator-authored YAML crosses into control-flow and reward-arithmetic values (`target_ladder`, `budget_cap`, `goal`). A hand-edit is the realistic mutation vector. |
| `rl/rewards.py::target_for_budget` → the GRPO gradient | The returned float is the denominator of `drop / target` in `drop_term` and `stealth_gate`. A degenerate value silently reshapes the whole reward surface rather than erroring. |
| Phase 1 config → Phases 2-5 result cells | The ladder defines the per-(defense × budget) cell structure Phase 2's normalizer, Phase 3's graded ASR and Phase 5's bandit are all keyed on. A silently wrong ladder corrupts every downstream number. |
