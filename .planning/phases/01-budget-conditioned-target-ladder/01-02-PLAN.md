## Phase Goal

**ROADMAP `**Goal:**` line, verbatim:** The attacker faces an accuracy-drop target that scales with the leverage it actually has this round, resolved everywhere through one function, and the bottom rung is confirmed measurable before anything is built on it.

> **MVP_MODE note:** this Goal line is not in user-story form; the planner does not invent one. See Plan 01 for the full note.

<objective>
Move the ladder from a code default into config, and retire the per-round target-sampling machinery it replaces — with the retirement enforced by a test rather than by a one-time grep.

Plan 01 made the budget → target path real using `DEFAULT_TARGET_LADDER`. This plan makes GOAL-02 true (the ladder is tunable from `configs/base.yaml` with no code edit) and GOAL-04 true (the retired keys are gone and nothing anywhere can read them again).

Purpose: the ladder values will move. GOAL-06 may raise the bottom rung this phase, and Phase 2's normalizer will make the rungs' relative spacing matter. If retuning requires a code edit, it will not happen; if a retired key can quietly reappear, an operator will believe target sampling is active when nothing reads it.

Output: `attack.target_ladder` in `configs/base.yaml`; the two retired keys and their comment block deleted; the phantom attribute write in `benchmark/run_benchmark.py` removed; `README.md`'s target-generalization paragraph rewritten around the ladder; and four new tests in `tests/test_target_ladder.py` including an automated tree-wide scan.
</objective>

## Flagged planner assumptions

1. **GOAL-02 (edge probe: `unclassified`)** — the probe could not classify "The ladder is declared in `configs/base.yaml` and can be re-tuned without a code change". Planner assumption: "re-tuned without a code change" means an env constructed from a config dict carrying a non-default `attack.target_ladder` resolves the non-default values, and the shipped `configs/base.yaml` declares a complete ladder. It does **not** mean the ladder is hot-reloadable mid-run, and it does not mean `DEFAULT_TARGET_LADDER` disappears — D-04 explicitly accepts the ladder numbers living in two files.
2. **GOAL-04 (edge probe: `unclassified`)** — the probe could not classify "no code path can still read them". Planner assumption: enforcement is a tree-wide token scan over version-controlled source, config, and documentation, excluding `.planning/` (per 01-PATTERNS.md those are requirement and history documents describing this very retirement, not readers) and excluding the scanning test file itself. If a reviewer wants `.planning/` in scope, that changes the exclusion list, not the mechanism.
3. **`benchmark/run_benchmark.py:197` in scope.** 01-PATTERNS.md's deletion sweep missed this line because it grepped only the config-key spellings, not the attribute name. Planner assumption: a write to an attribute this phase deletes is dead code that reads as live, so GOAL-04 covers it.
4. **The shipped-config test asserts structure, not literal values.** `test_shipped_config_declares_a_complete_ladder` checks coverage of `[1, max_poison_clients]` and strict monotonicity rather than the five exact numbers, so that a GOAL-06 rung raise in Plan 03 does not force an unrelated test edit. The exact locked values stay asserted once, in Plan 01's `target_for_budget` behavior check, which Plan 03 updates deliberately if and only if the measurement forces a raise.
